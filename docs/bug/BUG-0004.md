# BUG-0004 — Dimension legends show raw extraction notes

> Status: Resolved · Severity: Medium (readability across 3 modules) · Found: device QA 2026-09-03

## Summary

The legend text beside each dimension letter is the verbatim JSON `legend`
string, which was written for the extraction pipeline, not for users. On
the phone it reads like:

- Fittings SW: "elbow90/elbow45: end to opposite outside face (overall, per diagram)"
- Fittings SW: "minimum socket depth, printed 'D MIN.' (all SW tables: elbows, tees, crosses, laterals, quikLeg90, bossWithLip, coupling family)"
- Flanges: "Minimum thickness of flange (catalog C). Inside perType.LJ (Classes 150/300) it is the separate minimum lap joint flange thickness; inside perType.WN / perType.blind of B16.47 (NPS 30-48) rows it is the printed WN / BLD thickness"
- Branch connections: "Size-on-size tables only: opening (bore) diameter shown on the catalog end view, inches. For sockolet class 3000 size-on-size the catalog prints D as a decimal bore matching pipe ID."

Five-line legends push the values off screen and mention internal names
(`perType.LJ`, `quikLeg90`).

## Steps to Reproduce

1. Modules → Fittings → End **SW** → read the dims card.
2. Modules → Flanges → scroll to the dims card, row **C**.

## Expected vs Actual

- **Expected:** one short caption per letter ("End to opposite outside face",
  "Minimum socket depth", "Minimum thickness of flange").
- **Actual:** full provenance note, multi-line, with code identifiers.

## Root Cause

`FittingsView.legendText`, `FlangesView.dimRow` and `OletsView.dimsCard`
render `legend[key]` directly. The JSON notes are valuable provenance and
should stay in the data files; the UI needs a display form.

## Acceptance Criteria

- [x] A `LegendText.display(_:)` helper strips scope prefixes ("elbow90/elbow45:"),
      parenthetical notes, "catalog X" / "printed 'X'" asides, trailing
      ", inches" / "(row X)" and anything after the first sentence, then
      capitalises the result.
- [x] Applied in Fittings, Flanges and Branch Connections dims cards.
- [x] Unit tests on the legend strings above; a test that every bundled
      legend value survives the cleaner non-empty and without "(" or "perType".

---

## Resolution

New [`Support/LegendText.swift`](../../PipingDatabase/Support/LegendText.swift):
`LegendText.display(_:)` strips parenthetical notes, keeps the first clause,
drops a short scope prefix ("elbow90/elbow45:", "Sockolet only:"), removes
"printed '…'", "per (catalog) diagram", ", decimal", ", inches" asides and
capitalises. Fittings, Flanges and Branch Connections dims cards render the
cleaned caption; the JSON legends are untouched (provenance stays in data).
Tests: `BugRegressionTests.legendCaptions` (13 real legends) and
`everyBundledLegendCleansUp` (every legend value in the bundle: non-empty, no
parentheses, no `perType`, ≤ 90 chars, capitalised).

Verified: 60 unit + 5 UI tests green on the iPhone 17 Pro simulator (iOS 26.5), and re-checked on the iPhone 13 Pro (iOS 26.6.1) via WebDriverAgent on 2026-09-03 — the reproduction steps above now produce the expected result.
