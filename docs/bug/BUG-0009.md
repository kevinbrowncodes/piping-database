# BUG-0009 — Recents records the default selection on module open

> Status: Resolved · Severity: Low (noise in Recents) · Found: device QA 2026-09-03

## Summary

Opening Pipe Schedule from the module list — without touching a wheel —
writes "1/2" Sch 40 Pipe" to Recents 1.5 s later. Every visit bumps that
default row to the top of Recents, crowding out lookups the user actually
made.

## Steps to Reproduce

1. Fresh launch → Modules → Pipe Schedule → wait 2 s → Back → scroll to Recent.

## Expected vs Actual

- **Expected:** Recents only contains selections the user made (wheel change,
  or arrival via a favorite / recent / search deep link).
- **Actual:** 1/2" Sch 40 appears after merely opening the module.

## Root Cause

`PipeScheduleView.task(id: payload)` records on first run with the initial
payload, whether it came from a user or from the default `init`.

## Acceptance Criteria

- [x] No recent is written for the initial default payload unless the view
      was opened with a preselect (deep link) — subsequent wheel changes
      record as before.

---

## Resolution

`PipeScheduleView` remembers its initial payload and whether it was opened
with a preselect (deep link). The recents task returns early while the
payload is still the default and the view was opened from the module list;
wheel changes and deep-link arrivals record as before.

Verified: unit suite green on the iPhone 17 Pro simulator (iOS 26.5); device re-check on the iPhone 13 Pro recorded below.
