# BUG-0002 — Calculator +/− mishandles feet entries and later digits

> Status: Resolved · Severity: High (wrong numbers) · Found: device QA 2026-09-03

## Summary

The trade calculator's sign key negates only the feet *or* the inches part
of the entry being typed, and once pressed it turns the inch digits into a
decimal string, so further digits are appended after a decimal point.

## Steps to Reproduce

1. Calculator tab → AC → **5**, **feet**, **3**, **+/−**.
2. AC → **5**, **+/−**, **3**.

## Expected vs Actual

| Keys | Expected | Actual on device |
|---|---|---|
| 5 feet 3 +/− | −5'-3" | **−4'-9"** (−60 + 3 = −57") |
| 5 +/− 3 | −4'-5" (−53") | **−0'-5"** (digits became "-5.03") |

## Root Cause

`TradeCalcEngine.plusMinus()` negates `feetPart` alone when it exists, and
otherwise rewrites `digits` as `String(-v)` (e.g. "-5.0"), after which
`digit(_:)` appends characters to that decimal string.

## Acceptance Criteria

- [x] Sign is an explicit flag on the in-progress entry; `entryInches` applies
      it to the whole feet + inches + sixteenths value.
- [x] Digits typed after +/− extend the inch part normally.
- [x] Unit tests cover both sequences above plus +/− on a result and on the
      accumulator.

---

## Resolution

`TradeCalcEngine` now keeps an explicit `negative` flag on the entry;
`entryInches` applies it to feet + inches + sixteenths together, `plusMinus()`
toggles it (result/accumulator negate as before) and `clearEntry()` resets it.
Digits stay a plain digit string, so typing after +/− extends the inch field.
Tests: `signAppliesToWholeFeetInchEntry`, `digitsAfterSignExtendTheInchField`,
`signOnResultAndAccumulator`, `negativeEntryClearsAfterCommit` in
`TradeCalcTests`; `SmokeTests.testCalculatorSignNegatesWholeEntry` on the real keypad.

Verified: unit suite green on the iPhone 17 Pro simulator (iOS 26.5); device re-check on the iPhone 13 Pro recorded below.
