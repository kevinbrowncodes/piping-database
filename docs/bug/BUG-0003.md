# BUG-0003 — Flanges keeps a stale type when the class/size no longer offers it

> Status: Resolved · Severity: Medium (data shown does not match the wheel) · Found: device QA 2026-09-03

## Summary

Changing class or size to a row that lacks the current flange type leaves
`selectedType` at the old value. The Type wheel visually snaps to the first
available row ("Weld Neck") but the cards render for the stale type: no
weight row, no per-type dimensions, and the datasheet/share text names the
wrong type.

## Steps to Reproduce

1. Modules → Flanges → Type **Lap Joint**, Class 150, Size 2".
2. Spin Size to **30 A"** (B16.47 rows have only WN and Blind).

## Expected vs Actual

- **Expected:** type reconciles to Weld Neck; drilling card shows
  "Weight (WN) 400.0 lb"; dims card shows the Weld Neck section (C, Y1).
- **Actual:** wheel reads Weld Neck but the drilling card has no weight row
  and the dims card ends at W — the view is still rendering `LJ`.
- Same with Class **125** (WN/SO only) after choosing Threaded, Socket Weld,
  Lap Joint or Blind.

## Root Cause

`FlangesView.onChange(of: selectedClass)` only reconciles `selectedNPS`;
nothing reconciles `selectedType` against `availableTypes`, and size changes
have no handler at all.

## Acceptance Criteria

- [x] `selectedType` reconciles to the first available type whenever class
      or size changes and the current type is unavailable.
- [x] Pure helper with unit tests for the reconciliation rule.

---

## Resolution

`FlangesView` reconciles `selectedType` against `availableTypes` whenever
class or size changes (`reconcileType()`, pure rule in
`FlangesView.reconciledType(_:available:)`). Tests:
`BugRegressionTests.flangeTypeReconciles`, `class125OffersOnlyWeldNeckAndSlipOn`
(documents why the rule matters) and `SmokeTests.testFlangeTypeFollowsTheRow`
(LJ 2" → 30 A" shows "Weight (WN)").

Verified: unit suite green on the iPhone 17 Pro simulator (iOS 26.5); device re-check on the iPhone 13 Pro recorded below.
