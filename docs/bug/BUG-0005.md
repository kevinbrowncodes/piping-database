# BUG-0005 — Fittings weight card wraps six schedule columns on iPhone

> Status: Resolved · Severity: Medium (layout) · Found: device QA 2026-09-03

## Summary

Butt-weld elbows/tees carry up to six schedule weights (STD, 40, XS, 80,
160, XXS). The weight card lays them out in a single `HStack`; on a 390-pt
iPhone the labels break ("Sch\nSTD", "Sch\n160") and every value wraps its
unit onto a second line ("1.60\nlb"), so the card reads as two ragged rows.

## Steps to Reproduce

1. Modules → Fittings → BW, 90° Elbow LR, 2".
2. Look at the Weight card.

## Expected vs Actual

- **Expected:** every label and value on one line, columns flowing to a
  second row when they do not fit.
- **Actual:** mixed one- and two-line cells, "lb" orphaned under each value.

## Root Cause

`FittingsView.weightsCard` uses `HStack(spacing: 18)` with no
`fixedSize`/`lineLimit`, and six columns exceed the available width.

## Acceptance Criteria

- [x] Weight cells use an adaptive grid (`LazyVGrid` with `.adaptive`) so
      they wrap by cell, never inside a cell.
- [x] Verified by screenshot on iPhone (portrait) and iPad.

---

## Resolution

`FittingsView.weightsCard` uses a `LazyVGrid` with adaptive 84-pt columns;
each cell is `lineLimit(1).fixedSize()`, so six schedules wrap as whole cells
onto a second row and "lb" never orphans.

Verified: unit suite green on the iPhone 17 Pro simulator (iOS 26.5); device re-check on the iPhone 13 Pro recorded below.
