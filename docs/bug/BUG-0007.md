# BUG-0007 — iPhone landscape: pickers and tab bar leave the drawing clipped

> Status: Resolved · Severity: Low (usability in landscape) · Found: device QA 2026-09-03

## Summary

In landscape on an iPhone (844 × 390 pt) every module stacks the 130-pt
picker wheels under the content, above the tab bar. Roughly 160 pt remain
for the drawing + cards, so the drawing is cut through the middle and the
data grid is only reachable by scrolling inside that sliver.

## Steps to Reproduce

1. Modules → Pipe Schedule (or Fittings) → rotate the phone.

## Expected vs Actual

- **Expected:** content and pickers side by side when vertical space is
  compact, like the iPad layout puts drawing and data side by side.
- **Actual:** drawing clipped at the picker edge (see qa/136, qa/137 captures).

## Root Cause

Every module view is `VStack { ScrollView { … }; pickers }` regardless of
`verticalSizeClass`.

## Acceptance Criteria

- [x] A shared `ModuleLayout` container that uses an `HStack` (content left,
      pickers right) when `verticalSizeClass == .compact`, unchanged otherwise.
- [x] All seven modules adopt it; portrait and iPad layouts unchanged.

---

## Resolution

New [`Views/ModuleLayout.swift`](../../PipingDatabase/Views/ModuleLayout.swift):
content and pickers stack in regular height (unchanged 130-pt wheel bar) and
sit side by side when `verticalSizeClass == .compact`, with the wheels filling
the height on the trailing edge (360 pt; Fittings 420 pt for its five wheels).
All seven module views adopt it; picker sizing moved out of the views.

Verified: unit suite green on the iPhone 17 Pro simulator (iOS 26.5); device re-check on the iPhone 13 Pro recorded below.
