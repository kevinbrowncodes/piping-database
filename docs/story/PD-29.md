# PD-29 — Coverage gate: 95% on the app target, enforced locally

> Status: Open · Milestone: 5 — Post-launch · Size: M · Epic: [BACKLOG](../BACKLOG.md)

## Why

The project promises a 95% line-coverage gate (docs/TESTING.md, app-remake
non-negotiables) but nothing enforces it and the number is far below the bar.
Measured 2026-09-03 on the iPhone 17 Pro simulator (iOS 26.5) with the full
unit + UI suite:

| Target | Line coverage |
|---|---|
| PipingDatabase.app | **45.0%** |
| PipingDatabaseTests.xctest | 99.4% |
| PipingDatabaseUITests.xctest | 98.7% |

Per file, the gap is almost entirely views that no UI test opens:

| File | Coverage | Why |
|---|---|---|
| PipeCompareSheet.swift | 0% | compare sheet never opened |
| OletsView.swift | 0% | module never opened |
| ValvesView.swift | 0% | module never opened |
| GasketsView.swift | 0% | module never opened |
| FittingsView.swift | 0% | module never opened |
| LineBlanksView.swift | 0% | module never opened |
| SettingsView.swift | 5% | tab never opened |
| BoltProcedureSheet.swift | 10% | procedure / P-T sheets never opened |
| SavedLookup.swift | 22% | favorites/recents store untested |
| ModuleLayout.swift | 59% | compact-height branch untested |
| ModuleListView.swift | 72% | favorites/recents/reorder paths |
| ReferenceData.swift | 81% | `runRangeText`, `sourceLabel` branches |
| TradeCalcView / PipeScheduleView / TradeCalcEngine | 88–90% | keypad + menu paths |
| FlangesView / SearchIndex / Seeder / Units | 92–95% | edge branches |

Everything else is ≥ 97%.

## Plan

1. **Gate script** — `scripts/check.sh`: `xcodebuild test -enableCodeCoverage YES`
   on the pinned simulator, then `xcrun xccov view --report --json` and fail
   under 95% `lineCoverage` for the `PipingDatabase.app` target. Run before
   every milestone commit and before every App Store upload (no CI).
2. **One UI test per module** (Layer 4): launch with `OPEN_MODULE`, assert a
   golden value, spin every wheel once, tap the drawing (fractions), toggle
   units, open each sheet/menu the module has (compare, procedure, P-T,
   about, share). Fittings needs BW + SW + TH; Flanges needs a B16.47 row
   and Class 125; Olets needs a two-row run picker; Gaskets needs the FF
   toggle.
3. **Home-screen paths**: favorite → appears in Favorites → delete in Edit
   mode; recents after a wheel change; reorder persists across relaunch;
   Settings tab (every control) and its data-sources list.
4. **Store tests** (Layer 3): `LookupStore` favorite toggle, recent
   dedupe/cap, in-memory container.
5. **Landscape**: one UI test rotates the device (`XCUIDevice.shared.orientation`)
   and asserts the wheels are beside the content (ModuleLayout compact branch).
6. Keep logic out of view bodies as tests reveal glue; delete unreachable code
   rather than excluding it.

## Acceptance criteria

- [ ] `scripts/check.sh` exists, is documented in docs/TESTING.md, and fails
      the build when app-target line coverage < 95%.
- [ ] App target ≥ 95% line coverage with the full suite on the pinned
      simulator; per-file floor 85% for every file under `Views/`.
- [ ] Every module and every sheet is opened by at least one XCUITest that
      asserts a golden value on screen.
- [ ] Gate green before the next App Store upload after this story lands.
